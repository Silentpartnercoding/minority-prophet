# Crosswalk: W3C PROV-O → Memory Evidence Profile v0.1

A crosswalk, not a proposal. It maps the terms of the W3C PROV Ontology onto the
fields this profile already carries, says for each field whether PROV-O can
express it, and ends every row in a fixture that can be run.

Source for the left column: *PROV-O: The PROV Ontology*, W3C Recommendation,
30 April 2013, <https://www.w3.org/TR/prov-o/>, with definitions quoted from
*PROV-DM: The PROV Data Model*, W3C Recommendation, 30 April 2013,
<https://www.w3.org/TR/prov-dm/>. Read 14 September 2026.

## What this is, and is not

PROV-O is the published W3C vocabulary for provenance: which entity was
generated by which activity, used what, was derived from what, and which agent
was responsible. It is a finished Recommendation with real term names, so unlike
the memory crosswalk beside this file, the left column here is the standard's own
vocabulary rather than a scope description.

The purpose is narrow. Where this profile and PROV-O say the same thing, a
producer already emitting PROV can populate the profile from it. Where PROV-O has
no term, the row says so and names the failure that stays unobservable. Nothing
here proposes a PROV extension, and nothing here claims PROV-O is deficient for
its own purpose: PROV-DM describes provenance as information that "can be used
to form assessments about its quality, reliability or trustworthiness", and
leaves the assessment to the consumer. This profile is one such consumer.

|---|---|---|---|---|
| `prov:Entity`, `prov:value` | `claims[].id`, `claims[].value`, `claims[].claim_digest` | Yes, except the digest | A claim is an entity with a value. Content addressing has no PROV term and is carried by the profile. | `copied-consensus.json` |
| `prov:wasDerivedFrom`; or `prov:used` with `prov:wasGeneratedBy` | `claims[].derived_from` | Yes | The derivation edge that makes a copy collapse to its root. PROV can state it. Nothing in PROV requires it to be stated, so an unrecorded derivation leaves a copy indistinguishable from an original. | `copied-consensus.json`; adversarial `derived-claim-mints-root` |
| `prov:wasQuotedFrom`, `prov:wasRevisionOf` | `claims[].derived_from` | Yes, more finely | PROV distinguishes a quotation ("the repeat of (some or all of) an entity … by someone who may or may not be its original author") and a revision from other derivations. The profile collapses all three to one edge, because each makes the claim a descendant for counting. The subtype is lost, not the dependence. | `copied-consensus.json` |
| `prov:hadPrimarySource` | a claim with empty `claims[].derived_from` (a declared root) | Partly | PROV names a source "produced by some agent with direct experience and knowledge about the topic, at the time of the topic's study, without benefit from hindsight". The profile treats any parentless claim as a *declared* root and does not trust the declaration. In both, `hadPrimarySource` and parentlessness are assertions; neither establishes that the direct experience happened. | adversarial `fabricated-parentless-root` |

It cannot express the converse: that two agents with no recorded delegation are *independently* controlled. Absence of an `actedOnBehalfOf` statement is not evidence of independence. | `shared-control-verifier.json` |
| `prov:generatedAtTime` on the claim and on each source entity | `lifecycle.observed_at` | Yes, and further than the profile | The profile's freshness dates the cell, not the observation a derived claim rests on. PROV dates every entity separately, so a consumer that follows `wasDerivedFrom` to the source can read the age of the root. Here PROV carries information the profile does not. | `stale-derived-status.json` |
| `prov:invalidatedAtTime`, `prov:wasInvalidatedBy` | `lifecycle.expires_at`, `lifecycle.revocation_status` | Partly | PROV defines invalidation as "the start of the destruction, cessation, or expiry of an existing entity by an activity". It can say an entity was invalidated. It has no term for `revocation_status: unknown`: an entity with no invalidation statement reads as current. | adversarial `revoked-evidence-support`, `unknown-revocation-support`, `invalid-lifetime` |
| *(no term)* | `lifecycle.nonce` | No | Replay detection has no PROV counterpart. | `adversarial-cases.json` |
| `prov:Activity`, `prov:used`, `prov:hadPlan` | `conclusion.method`, `conclusion.input_claims` | Yes | A conclusion as an activity that used named claims under a plan. | adversarial `unknown-conclusion-input` |
| *(no term)* | `conclusion.kind`, `conclusion.strength`, `conclusion.uncertainty` | No | PROV records how a conclusion was produced, not what it concludes or how strongly. | `incomplete-search.json` |
| *(no term)* | `binding.proposition_digest`, `binding.memory_object_digest`, `binding.request_digest`, `binding.action_digest` | No | PROV relates entities to activities and agents. It has no relation saying an entity is evidence *for a proposition*, or that an assessment is bound to a request or action. `prov:specializationOf` and `prov:alternateOf` relate two entities that present aspects of the same thing; they do not bind evidence to a claim. | adversarial `malformed-binding`; `opaque-memory-cell.json` |

## What PROV-O cannot express, and the failure each leaves

Five distinctions the profile carries have no PROV-O term. Each is stated as the
failure that stays unobservable to a consumer holding only PROV.

1. **Distinct-root cardinality.** PROV can state every derivation but defines no
   count over them and does not require any to be stated. Three authentic
   entities quoted from one observation, with the quotation edges omitted, read
   as three primary sources. → `copied-consensus.json`
2. **Search coverage.** A search that reached 1 of 26 partitions and found
   nothing leaves no entity. Absence of evidence and evidence of absence are the
   same PROV graph. → `incomplete-search.json`
3. **Authentication of an assertion.** A bundle can be attributed to an agent;
   whether that attribution was verified is not representable. → adversarial
   `fabricated-parentless-root`
4. **Unknown revocation.** An entity with no invalidation statement is
   indistinguishable from one whose revocation status could not be determined.
   → adversarial `unknown-revocation-support`
5. **Binding evidence to a proposition or action.** Nothing ties an entity to the
   claim it is offered as evidence for. → adversarial `malformed-binding`

And one place PROV-O expresses more than the profile: source entities carry their
own `generatedAtTime`, so the age of a derived claim's root observation is
recoverable by walking derivations. The profile's `stale-derived-status.json`
records that its own freshness fields cannot do this.

## Running the fixtures

```sh
python3 interop/memory-evidence-profile-v0.1/validate.py
```

Python standard library only. No PROV tooling is required; the rows above name
fields and cases, not a PROV serialization.
