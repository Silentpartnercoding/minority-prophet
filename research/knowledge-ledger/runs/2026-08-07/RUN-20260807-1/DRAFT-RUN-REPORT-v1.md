## ELI5

We are building a way for machines to pass a fact to each other without lying
by accident.

Two things can go wrong when you ask "is there a problem here?"

The first: someone photocopies one report twenty times and hands you the stack.
It *looks* like twenty people agree. It is one person, twenty times. Copies are
not witnesses.

The second: you check three rooms out of five, find nothing, and announce the
building is empty. You did not look everywhere. "I found nothing where I looked"
is not "there is nothing."

This run tested one small program that is supposed to never make either mistake.
We tried it on **every possible tiny world** we had defined — 176,120 of them,
not a sample, all of them — and then on a million random bigger ones. It never
made either mistake.

Then we did something that matters more, and that is easy to skip. We built four
**deliberately broken** versions and checked that our test could actually catch
them. It caught all four. Without that, "our test found no problems" might only
have meant our test could not see problems.

We also attacked it ten ways. It held against most. **It did not hold against
one**, and that one is worth understanding: if you get to say which rooms exist,
you can leave out the room with the problem in it. Then you searched "every"
room, honestly, and found nothing. The paperwork is perfect. The answer is
wrong. Our program cannot detect this, because the list of rooms arrives already
written.

So: the little machine keeps its promises. Whether the promises are the right
ones to make is a different question, and we wrote down that we have not
answered it.

**What we did NOT do.** We did not send anything between two systems. That was
the goal, and we did not get there, because doing it honestly needs a second
program written by someone who has not seen ours. We have one program, checked
carefully by the people who wrote it. That is worth something, and it is not the
same thing.

## Strongest supported claim

> Within the declared bounds, the reference evaluator did not allow a recorded
> copy to change evidential mass, and did not allow an incomplete search to
> yield an absence conclusion. Four ablated evaluators removing exactly those
> properties were each detected by the same checker.

Bounded by: 176,120 exhaustive worlds inside the declared bounds; 1,000,000
randomized worlds from one frozen seed; one evaluator; one author; one machine.

### The number needs a qualifier

**75.7% of randomized worlds fail closed** and never produce a receipt, so eight
of the ten invariants were exercised on **243,381** randomized worlds, not
1,000,000 — roughly twice the exhaustive phase, not four times. The honest 95%
rule-of-three bound for those eight is **1.23 × 10⁻⁵** per receipt-producing
world, against 3.0 × 10⁻⁶ per drawn world. Both are true; they answer different
questions.

Every refusal in both phases decomposes to the single expected
`ValueError: One root cannot support opposing sides.` — zero unexpected causes,
receipts and refusals reconciling exactly to worlds drawn. Until that was
bucketed, "0 violations across 1,000,000 worlds" was **not readable as written**,
because three-quarters of those worlds errored for reasons the record did not
contain.

That the dual ledger recovers truth. That declared roots are genuinely

**And the one that matters most:** that a bounded-absence conclusion is

## What broke, and what it cost

Seven adversarial limits (`ADV-001`..`ADV-007`) and seven provenance/scientific
constraints. The provenance failures deserve attention because **three of them
are the same error the program exists to prevent, occurring in the program's own
record-keeping**:

- `PROV-004` — the prompt digest was computed over bytes the agent
  **transcribed from its own context**. Off by 4 bytes: two curly quotes
  normalised to straight. Internally consistent, self-digesting, wrong. Caught
  only by the operator's independent capture, made before the session began.
- `PROV-005` — the `github` remote had been **deleted** while its tracking refs
  survived. `github/main` resolved cleanly, two commits stale, and a file check
  returned 8/11 with no error. A cache measured and reported as the remote.
- `PROV-007` — a reviewed results commit was **amended away** rather than
  corrected by a follow-up, applying a weaker preservation standard to a result
  than this same run had applied to an orientation note three commits earlier.

Each is a derived copy silently standing in for its source, locally
unfalsifiable, detectable only from outside. That is precisely what KL-000's
copy-invariance invariant makes impossible **inside the evaluator** — and it
happened three times in one run in the layer where no invariant was watching.

The uncomfortable one is `PROV-007`. This run *wrote* methodology note M2 —
warning that amending makes an amendment log unfalsifiable — and then amended a
reviewed commit two commits later. Stating a principle is not holding it, and
the gap was invisible from the inside. That is an argument for mechanical
enforcement (`BL-011`), not for trying harder.

**All three were found by the operator, not by the agent.** A run that reports
its own provenance is exactly as reliable as a system that counts its own
copies.
